# 二面创意作品：演示与验收

## 1–2 分钟演示

1. 运行 `npm run dev`，打开 `http://localhost:5173`，进入随笔页。说明产品解决“中文记录与英语表达练习”这一具体需求。
2. 新建随笔本，输入一段不含个人隐私的中文随笔；切换随笔后重新打开，展示本地保存。
3. 在 AI 设置中保存自己的 Key（保存会先测试连接）。点击分析，展示任务进度、英文翻译、金句和词汇语法结果；只有真实调用成功后才能说这一部分已验收。
4. 导入明确标注的 50 篇虚构演示随笔，进入独立演示随笔本，展示知己解锁和对话入口。样例导入本身不调用模型；真实对话会调用。
5. 导出 JSON 备份，说明 IndexedDB 按浏览器来源隔离，换设备或端口需主动导入。

没有 Key 时可演示编辑、词库、样例导入、解锁和备份。模型未返回时应展示错误提示，不把预置内容解释成真实模型结果。

## 需要讲清楚的技术

| 问题 | 实际解释 |
| --- | --- |
| 主程序做什么？ | React 入口挂载组件并组装路由；Node 入口组装服务并启动，具体职责放在功能模块。 |
| 如何前后端解耦？ | 前端提交 AI 任务，通过 SSE 订阅状态和结果；后端调用模型并解析结果。前端保留 UI 状态和用户本地数据。 |
| Key 存在哪里？ | 本机后端环境或忽略提交的设置文件，浏览器构建不包含 Key，查询设置不返回完整 Key。 |
| 是否训练了自己的模型？ | 没有。调用现成模型，根据随笔上下文归纳表达风格，再用于对话提示。 |
| 词库如何减少重复调用？ | 本地词表和已生成词条在 IndexedDB 复用；缓存不是模型训练。 |
| 50 篇样例说明什么？ | 仅用于展示当前随笔本的解锁流程，是明确标注的虚构素材，不能当作真实用户数据。 |
| 个人随笔是否一直上传？ | 平时本地保存；用户请求分析或对话时，相关内容会发给后端和配置的模型提供方。 |

## 验收记录方式

代码检查、接口自动化、真实模型调用、浏览器展示分别记录结果和日期。构建通过不代表云端调用成功，样例导入不代表真实用户积累；Key、账户权限和网络需要在本人环境中验证。

2026-10-10 实测：类型检查和生产构建通过；Lint 0 错误、0 警告；47 项自动化检查中 46 通过，1 项 Windows 文件符号链接权限跳过，目录 junction 越界检查实际通过。用户在本机页面保存 Key 后，使用虚构文本完成翻译/金句、单句、单词、画像和带历史的对话共 5 次真实 DeepSeek 调用，全部经 HTTP 任务和 SSE 返回完成。没有读取个人笔记。内存 IndexedDB 测试验证演示导入幂等与异步状态隔离；真实浏览器完整编辑、刷新持久化和视觉展示尚未单独验收。

原始方案中的声音克隆、人脸扫描、数字人、多设备同步与模型微调未作为本次完成项。它们属于规划，演示时不作完成承诺。
