Use the existing research API at `http://127.0.0.1:8000`; the corresponding MCP server is `aiu-research`. Start the app with `scripts/start.ps1` if it is stopped. Read `docs/checklist.md` and `docs/research-workbench.md` in the project before continuing an existing study.

Two tasks are registered: `digits_robustness` and `yolo_tradeoff`. Select a task explicitly; the page defaults to YOLO, while API/script/MCP compatibility defaults remain digits. Preserve the user's goal, but do not imply that the goal automatically changes datasets, methods or executable code. General domains and arbitrary generated-code execution remain unimplemented. Research and venue planning are advanced/exploratory materials, not default interview deliverables.

- `digits_robustness`: fixed sklearn digits classification, Gaussian training augmentation versus a shared unaugmented control, schema-checked Logistic Regression/Random Forest recipes. Standard study: 18 fits; a reduced single-candidate study: 15.
- `yolo_tradeoff`: same existing YOLO weights, input sizes 320/480/640, FP32, batch=1; mAP50/mAP50-95 and warmed end-to-end latency/FPS. Five evaluation jobs, zero training; no architecture changes. Current COCO128 run excludes eight known COCO8 images and two missing-annotation samples, then splits 59/59 for selection/evaluation. Pretraining overlap remains possible; this is not independent generalization evidence.

- Inspect `research_capabilities` and `research_list_runs` first. Reuse a matching active run.
- Start authorized work with `research_start`, an explicit `domain` and a stable request ID. Leave resource limits unset by default; apply a time, call or experiment-job limit only when the user asks for one. Actual usage remains recorded. Retrying after a lost response must keep both ID and payload.
- Use `research_get_run` compact output and cursor-based `research_events`; fetch full outputs only when needed. Completed steps are reused by the graph and journal.
- `research_resume` records an agent recovery and retains actual usage, including any explicitly configured limits. YOLO reuse checks frozen `yolo_runner_source.py` against the executing source SHA256; a mismatch must fail without overwriting old artifacts. Do not bypass source/integrity failures or repeatedly resume an exhausted budget. The completed YOLO case included developer repairs; recovery counters alone do not prove autonomous code debugging or absence of human intervention.
- Request user action only for a concrete blocker requiring it, such as unavailable account access or missing author details. Hardware was confirmed complete by the user on 2026-10-10; do not list it as missing or infer an unconfirmed PID level. Record the exact blocker and attempted automatic recovery.
- Verify final files with `research_artifact`. Cite actual source reading scope. Extracted PDF text does not prove formulas and tables were understood correctly.
- Paper roles may use configured DeepSeek/OpenAI, existing Codex CLI login or a recorded local fallback. Never copy, request in chat or expose API secrets. For a missing DeepSeek key, direct the user to the local page's paper model settings: test the connection and save to enable it immediately. A blank key can reuse the saved key. Connection testing reads the model list; it is not evidence of a successful paper generation. Credentials belong in the ignored `configs/.env` or environment variables; manual file changes require restart, while the settings API updates the writer immediately after verified persistence.
- Numeric manuscript claims come from raw CSV and artifact hashes. Keep degradation and failed experiments. For digits, baseline and no-augmentation ablation are one control alias; seed SD is not a confidence interval. For YOLO, `latency_ms` is the mean, FPS is `1000 / mean latency`, and repeated timing samples are correlated. Preserve that the completed run's selected 480 configuration was slightly slower than 640 on the frozen evaluation split. Keep unverified model analysis separate from measured claims.
- Review-driven prose revision uses the same frozen measurements. Adaptive experiments after test exposure need a fresh independent evaluation protocol; repeating the same holdout does not create independent confirmation.
- Archives preserve evidence, not portable frozen replay. A standalone frozen replay entry point and independent fresh-environment reproduction are not implemented; current project modules produce new measurements. Do not advertise an archived script as directly runnable independently or treat matching hashes as reproduction success.
- `/research/strategy` exposes three initial ideas, three journals' official requirements and an editor inquiry draft from `docs/yolo-ideas-and-venues.md` and `docs/editor-inquiry-draft.md`. These are fixed planning materials; automatic idea discovery, closest-work full-text difference matrices and journal background research do not yet drive execution decisions. The user prioritizes that integration. Preserve source dates, distinguish draft from sent correspondence, and do not promise acceptance.
- Workflow completion, candidate-report quality, novelty, external review, submission and acceptance are distinct states. Submission bundles do not prove a paper was submitted or published. External publication requires a concrete target and user authorization.

If MCP is not connected, the same endpoints are documented in `docs/research-workbench.md`; use the API directly rather than asking the user to transfer results manually.
